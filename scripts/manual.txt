RinkDesk data manual
Amateur tournament desk · ice 5-on-5 · summer roller 4-on-4
Commands:  ./start.sh

────────────────────────────────────────────────────────
1. Sign in

  Roles — and only these:

    admin  clerk. Licenses, teams, schedule, everything.
           Creating a team creates its only login (username = short name).
    ref    referee. Approve lineups, enter protocol, confirm.
           Cannot register people, create teams, or schedule matches.
    team   one account per club. Own roster and own lineup only.
           Cannot approve, cannot enter protocol, cannot schedule.

  Built-in clerk logins (change them in Settings):

    admin / admin     ref / ref

  Importing a snapshot also restores one login per club (short name).

  Language: Polish is the default. Switch PL / EN on the login card,
  in the top bar, and under Settings.

────────────────────────────────────────────────────────
2. What this is

  A rink clerk’s book: licenses, teams, match lineups, protocols, and
  a results tab with the table and the game list. It is an administrative
  tool, not a fan dashboard: player stats live on the public live page.
  Data lives on the server.

────────────────────────────────────────────────────────
3. Screens

  Desk        today’s matches and the next required action
  Licenses    master register — a person is entered once
  Teams       club cards, kit colours and logo; open a team to assign
              players (the logo is a PNG in team-logos/, matched by short name)
  Matches     schedule, then open the match desk
  Results     the table (or cup ladder) and the game list; download a
              confirmed protocol straight from the list
  Settings    tournament name, period clock, snapshot export/import,
              protocol JSON export

  The public live page is separate and not linked as a screen: open
  http://<host>:8765/live/ (the LIVE button in the top bar does this).
  It shows the table, games, goal leaders, assists and penalties to fans.

────────────────────────────────────────────────────────
4. Official workflow — no skips

  scheduled → lineup submitted → BOTH lineups approved → protocol confirmed

    1. Register licenses (active only can be assigned or dressed).
    2. Create teams. Assign from the license list.
       Jersey unique on that team. One C, max two A.
    3. Schedule a match. Home ≠ away.
    4. Match desk → pick players → Save draft → Submit.
    5. Approve both sides. Protocol stays locked until then.
    6. Enter goals and penalties. Score is the goal count. Type the time the
       way the tournament reads its clock; Settings → Period clock decides
       whether the desk and live page read it counting up or counting down.
    7. Confirm protocol. Only then does it hit the table.
    8. Save the protocol: the match desk writes the match PDF to disk.
       Every match keeps one file; saving again replaces it. The protocol
       always fits on one page — if a game has many goals or penalties,
       the list continues on extra pages that repeat the template and the
       rosters, and the signatures stay on the first page.

────────────────────────────────────────────────────────
5. Ice vs roller

                    Ice 5-on-5                   Roller 4-on-4
  On surface        1 G + 5 skaters              1 G + 3 skaters
  Club roster max   20 skaters + 2 G             10 total
  Lineup            min 6 (incl. 1 G)            min 4 (incl. 1 G)
                    max 20 skaters + 2 G         max 8, at most 2 G
  Periods           1 2 3 OT SO                  1 2 3 4 OT SO

────────────────────────────────────────────────────────
6. Files and folders

  The desk keeps three kinds of files:

    snapshots   whole-app export (Settings → Export); newest is imported
    protocols   one PDF per confirmed match, replaced on every save
    team-logos  image files you drop in yourself (no upload in the app)

  ./start.sh --start                    keeps current Postgres data
  ./start.sh --update                   rebuild from the local source (if
                                        present) or pull newer images, then
                                        recreate the app containers; keeps data
  ./start.sh --start --export-path DIR  write snapshots into a local folder
  ./start.sh --start --protocols-path DIR
                                        write protocol PDFs into a local folder
  ./start.sh --force-recreate           wipes the database, JSON snapshot
                                        volume, and protocol PDFs; starts empty
                                        with only the built-in clerk logins.
                                        Team logos are kept (app defaults).
                                        The shipped default snapshot stays
                                        available to import on demand from the
                                        login screen.
  ./start.sh --manual                   this manual

  Snapshots default to the Docker volume rinkdesk-exports; protocol PDFs go
  to the protocols/ folder next to start.sh. Pass the flags on every start,
  or set RINKDESK_EXPORTS_PATH / RINKDESK_PROTOCOLS_PATH for another folder.

  Team logos: there is no upload and no per-team setting. Drop a PNG into
  team-logos/ next to start.sh, named {short}_logo.png with the ASCII slug of
  the short name (ORŁY → orly_logo.png). A missing file just shows a neutral
  crest. The logo appears on the live page and on the printed protocol.
  Snapshot export copies these files next to the JSON; import restores them.
  See team-logos/README.md.

────────────────────────────────────────────────────────
7. Refusals (the API will reject these)

  duplicate license number · duplicate jersey on one team
  player outside the license list · suspended license in a lineup
  protocol before both approvals · points before confirm
  a team playing itself
